Monitoring Cronos-AI work

Navigate the dashboard, review approvals, and recover or abandon tasks.

Build the release binary with cargo build --release, then run scripts/cronos-ai to open the dashboard. Outside Herdr, the launcher starts Cronos-AI in its dedicated cronos-ai Herdr session; inside a Herdr pane, it opens the TUI directly in that pane. For a TUI in the current terminal, you can still run target/release/cronos-ai without a subcommand, but supervised task execution requires Herdr. The dashboard checks for pi, herdr, openspec, and git; if any are missing, it asks you to install them and press Enter to retry. It never installs tools automatically.

Navigation

  • Projects: use ↑/↓ to select a project and Enter to open its task list. Active and archived projects are shown so archived work remains inspectable. Press n to create a project with a name, description, repository, and check command.
  • Tasks: use ↑/↓ to select a task. Each row shows status, priority, and current workflow step. Press Enter for details. Press s to start the next priority- and dependency-ready task, or to resume the active In Progress task when no orchestrator is running for it. Starting requires a repository, a check command, and a Herdr-managed session.
  • Task details: status, priority, attempt, automatic revisions (n/3), the current step and how long it has been running, the worktree, branch, and OpenSpec change, then human decisions, recovery context, and agent activity. Use ↑/↓ to select an activity update.
  • Review view: press v in task details to read the OpenSpec change, the task-branch commits, the diff summary against the base, and the latest check output. A warning at the top flags a task branch that changed the check program. Use ↑/↓ to scroll, PgUp/PgDn to page, and Esc or Backspace to return.
  • At the specification or final-code approval step, press y to approve or n to request revisions and enter a note. A revision returns the workflow to specification generation or code generation without changing the task from In Progress. Final-code approval unlocks documentation; Rust merges the task branch locally after Pi settles. No remote push is performed.
  • For an Error task, press t to retry only the failed step (same attempt, worktree, and approvals), r to discard the attempt and retry from specification generation, or c to enter clarification context and regenerate specifications. These actions wait if a step process still owns the task, and first stop agents a crashed orchestrator left running.
  • Press a in task details to abandon the task; enter a reason to mark it Rejected. Backspace/Esc cancels an open dialog or returns one level; r refreshes immediately (outside an Error task's details) and q exits.

The dashboard refreshes persisted project and task state once per second, so status, step, and activity updates written by the workflow host appear without restarting. An error message stays visible until your next key press. Activity is kept per task with a 100-event limit; older task files without activity data remain readable and show an empty activity panel.
